# Дайджест НКГ - события культуры Санкт-Петербурга

Автоматический дайджест событий участников «Новой культурной географии»:
дизайн, современное искусство, стрит-арт, креативные пространства.
Раз в день - анонс ближайшей недели, раз в неделю - большой обзор.

## Как это устроено (простыми словами)

**База участников** - файл [`data/participants.yaml`](data/participants.yaml).
Список мест с адресами и ссылками, откуда брать новости (сайт, ВКонтакте,
Telegram), и страницей афиши `events_url`.

**Агент 1 - «Реестр»** ([`agents/agent1_registry.py`](agents/agent1_registry.py)).
Проверяет ссылки, находит на сайтах афиши и соцсети, дополняет базу.
Читает «входящие» [`data/inbox.md`](data/inbox.md) - правки от человека.

**Агент 2 - «Дайджест»** ([`agents/agent2_digest.py`](agents/agent2_digest.py)).
Заходит на страницы афиш, моделью (GigaChat) достает события на неделю
(что, когда, где), собирает дайджест и кладет в `digests/`.
Отправка в Telegram - следующий шаг.

**Агент 3 - «Стрит-арт радар»** ([`agents/agent3_streetart.py`](agents/agent3_streetart.py)).
Следит за Telegram-каналами про уличное искусство (список -
[`data/streetart_sources.yaml`](data/streetart_sources.yaml)), ищет новости о новых
муралах, арт-объектах, уличных инсталляциях и стрит-арте Петербурга (граффити не берём), отсеивает лишнее моделью и собирает
блок «Новое на стенах города». Помнит показанное в `data/streetart_seen.json`,
чтобы не повторяться. Каналы читаются через веб-витрину `t.me/s/<канал>` без токена.

**Агент 4 - «Персона недели»** ([`agents/agent4_person.py`](agents/agent4_person.py)).
Всю неделю копит, кого чаще упоминают в событиях (художники, кураторы, лекторы,
режиссеры). В пятницу присылает владельцу в личку топ-3 кандидата, владелец
отвечает боту цифрой 1, 2 или 3. В субботу агент берет выбранного, просит модель
написать несколько фактов и публикует пост. Память - `data/person_tally.json`
(счетчик) и `data/person_choice.json` (кандидаты и выбор).

**Публикатор** ([`agents/publisher.py`](agents/publisher.py)) - «редактор недели».
Смотрит в [`data/themes.yaml`](data/themes.yaml), какая тема у сегодняшнего дня,
и собирает пост только по ней. График по дням:

| День | Тема |
|---|---|
| Понедельник | стрит-арт, выставки, галереи |
| Вторник | театры и кино |
| Среда | лекции и мастер-классы |
| Четверг | маркеты, коллаборации, события |
| Пятница | планы на выходные и гастрономия (+ выбор персоны) |
| Суббота | персона недели |
| Воскресенье | анонс следующей недели по всем темам |

Темы можно менять в `themes.yaml` (какие категории площадок и виды событий брать)
без правки кода. В каждом событии стоит ссылка на его страницу.

**Модель** - через [`agents/llm.py`](agents/llm.py). По умолчанию GigaChat
(оплата в рублях), запасной вариант - Anthropic. Ключи берутся из `.env`.

## Где это работает, когда компьютер выключен

Конвейер крутится в облаке на GitHub Actions по расписанию (бесплатно).

- **Вечер (21:00 МСК)** - предпросмотр: публикатор собирает список событий
  ЗАВТРАШНЕЙ темы по релевантности и шлет вам в личку на выбор. Вы отвечаете
  номерами, что оставить. По пятницам вечером приходит черновик карточки
  персоны недели ([`.github/workflows/preview.yml`](.github/workflows/preview.yml)).
- **Утро (08:00 МСК)** - публикация: выходит ваша выборка, а если вы не ответили
  до полуночи - авто-топ по релевантности (день до 10, неделя до 20 событий)
  ([`.github/workflows/daily.yml`](.github/workflows/daily.yml)).
- **Воскресенье (07:00)** - агент 1 обновляет базу
  ([`.github/workflows/weekly.yml`](.github/workflows/weekly.yml)).

База и память (показанные муралы, счетчик персон, список предпросмотра) - в
репозитории, ключи - в секретах GitHub. Для личных сообщений нужен секрет
`TELEGRAM_OWNER_CHAT_ID` (ваш чат с ботом, см. `.env.example`).

## Как запустить руками (для проверки)

```
py -m pip install -r requirements.txt

# агент 1: проверить базу / внести правки
py agents/agent1_registry.py
py agents/agent1_registry.py --apply

# агент 2: посмотреть формат без ключа и сети
py agents/agent2_digest.py --self-test
# дайджест со ссылками на афиши (без модели)
py agents/agent2_digest.py --no-llm
# полный сбор моделью (нужен ключ GigaChat в .env)
py agents/agent2_digest.py

# агент 3: стрит-арт радар
py agents/agent3_streetart.py --self-test       # формат на примере, без сети
py agents/agent3_streetart.py --no-llm --days 14 # только по словам-признакам

# публикатор: тематический пост по дням недели
py agents/publisher.py --self-test              # показать график и формат
py agents/publisher.py --day tuesday            # собрать конкретный день (с моделью)
py agents/publisher.py --send                   # сегодняшний день, собрать и отправить

# агент 4: персона недели
py agents/agent4_person.py --show               # текущий счетчик упоминаний
py agents/agent4_person.py --propose --send     # отправить владельцу топ-3 (пятница)
py agents/agent4_person.py --publish --send     # опубликовать персону (суббота)

# архив найденного (накопление для аналитики)
py agents/archive.py --stats                    # сводка за все месяцы
py agents/archive.py --month 2026-06            # сводка за месяц

# паблики ВКонтакте для стрит-арт радара (нужен ключ VK_TOKEN)
py agents/vk_source.py --check                  # ключ на месте и работает?
py agents/vk_source.py --groups a,b,c           # что за группы, годятся ли радару
py agents/vk_source.py --posts lenstreet        # последние посты сообщества

# городская афиша KudaGo (открытый API, без ключа)
py agents/kudago.py --sample                    # что придет по теме сегодня
py agents/kudago.py --day monday                # то же для конкретного дня
py agents/kudago.py --raw exhibition            # сырая выдача рубрики, для отладки

# журнал публикаций канала и подписчики
py agents/postlog.py --stats                    # что публиковали, сбои, подписчики
py agents/postlog.py --month 2026-08            # то же за месяц
py agents/postlog.py --subscribers              # снять число подписчиков сейчас

# история канала: что реально вышло и сколько просмотров (витрина t.me/s)
py agents/channel_history.py --backfill         # пройти весь архив канала
py agents/channel_history.py --refresh 40       # освежить просмотры свежих постов
py agents/channel_history.py --stats            # посты, просмотры, пропущенные дни
```

## Ключ модели (YandexGPT)

1. Войти в Yandex Cloud: console.yandex.cloud (по Яндекс-аккаунту).
2. Создать платежный аккаунт (оплата в рублях; для новых есть грант).
3. Открыть каталог (folder) и скопировать его идентификатор - строка вида `b1g...`.
4. Каталог -> Сервисные аккаунты -> создать аккаунт, дать роль `ai.languageModels.user`.
5. Открыть этот сервисный аккаунт -> создать ключ -> **API-ключ**, скопировать секрет.
6. Скопировать `.env.example` в `.env` и вписать:
   `YANDEX_API_KEY=...` и `YANDEX_FOLDER_ID=...`.

Запасной вариант - GigaChat: `LLM_PROVIDER=gigachat` и `GIGACHAT_CREDENTIALS=...`.
Файл `.env` в репозиторий не попадает (защищен `.gitignore`).

## Telegram (бот и канал)

Как завести (один раз):

1. В Telegram открыть **@BotFather** -> `/newbot` -> задать имя и username.
   BotFather выдаст **токен** - вписать в `.env` как `TELEGRAM_BOT_TOKEN`.
2. Создать **канал** (проще публичный, с адресом вида `@nkg_afisha`).
3. В настройках канала -> Администраторы -> добавить вашего бота,
   дать право «Публикация сообщений».
4. Указать `TELEGRAM_CHAT_ID` в `.env`:
   - публичный канал: `@nkg_afisha`;
   - закрытый канал: числовой `-100...` (узнать командой `--updates`,
     предварительно опубликовав в канале любое сообщение).
5. Проверить связь и отправить дайджест:

```
py agents/notify_telegram.py --test          # должно прийти сообщение в канал
py agents/notify_telegram.py --updates       # показать chat_id виденных чатов
py agents/agent2_digest.py --no-llm --send   # собрать и сразу отправить
```

## Источники событий

Событий два потока, оба проходят через одни правила публикатора (типы темы, порог
релевантности, черный список площадок, архив):

1. **Свой сбор** - агент 2 идет по сайтам площадок из `data/participants.yaml`.
   Точно, но видит только то, что есть в базе.
2. **Городская афиша KudaGo** - `agents/kudago.py`, открытый API без ключа. Дает
   события на площадках вне базы. Отбор задан в `data/kudago.yaml`: нужные рубрики,
   стоп-слова по площадке, названию, описанию и меткам, порог релевантности (для
   незнакомой площадки он выше), предел событий с одной площадки, список
   соответствий названий (`place_aliases`).

Названия площадок у KudaGo свои («Главный штаб (Эрмитаж)», «Парк «Новая Голландия»»),
поэтому сведение с базой идет по вхождению названия и по списку соответствий.
Угадывание по общим словам не используется: оно подтягивало «Музей истории религии»
к Музею истории Петербурга.

Дубли между потоками отсекаются по названию события. Сбой KudaGo не роняет выпуск -
публикатор просто выйдет со своим сбором.

## Стрит-арт радар: правило «одна работа - один раз»

Сбор находок живет в одном месте - `agent3_streetart.collect_items`. Им пользуется и
сам агент 3, и публикатор в утреннем дайджесте. Раньше публикатор собирал радар
своим кодом, поэтому правило о повторах на канал не действовало: в дайджест
попадало то, что радар уже показывал.

Радар помнит две вещи (`data/streetart_seen.json`):

- **разобранные посты** по адресу - чтобы не гонять модель по одному и тому же
  посту дважды (храним 120 дней);
- **сами работы** - потому что об одном мурале пишут разные каналы в разные дни,
  и памяти по адресу поста для этого мало (храним 240 дней).

Как сверяются работы: по совпадению значимых слов, а не строк - одну новость каждый
пересказывает по-своему. Самый сильный признак - **адрес**: у работы на Некрасова,
52 он один, как бы про нее ни написали. Совпадение адреса считается признаком одной
работы, только если сообщения близки по времени (45 дней для адреса с типом улицы,
30 для вида «Некрасова, 52»): по тому же адресу через полгода может появиться уже
другая работа, легальные стены перекрашивают.

Старый формат файла (просто список адресов постов) читается по-прежнему и при первой
записи переходит в новый вид сам.

## Стрит-арт радар: два вида источников

- **Телеграм-каналы** читаются через веб-витрину `t.me/s/<канал>` - без токена и
  регистрации. Каналы художников помечаются `kind: artist`: их посты идут к модели
  без фильтра по словам-признакам, потому что художник пишет «название, адрес», а
  не «мурал». Город при этом проверяет модель.
- **ВКонтакте** читается через API по ключу `VK_TOKEN`. Анонимно ВК не отдает ни
  постов, ни даже названия сообщества, поэтому ключ обязателен. Без ключа радар
  молча пропускает ВК и работает на телеграме, как раньше. Два способа:
  - *поиск по всему ВК* (`vk_search` в настройках) - основной. Не привязан к
    списку групп, находит работы у кого угодно. Отбор внутри: слово темы,
    признак Петербурга, стоп-слова (реклама, закупки), склейка повторов и
    проверка города автора по API - без нее половина выдачи оказывается из
    Перми и Красноярска, где Петербург просто упомянут в перечислении;
  - *список сообществ* (`vk_groups`) - для тех, что читаем всегда.

Ключ ВК: dev.vk.com -> «Мои приложения» -> создать приложение типа Standalone ->
скопировать «Сервисный ключ доступа» -> положить в `.env` и в секреты GitHub как
`VK_TOKEN`. Проверка: `py agents/vk_source.py --check`.

Что сервисный ключ умеет (проверено 2026-08-26): `wall.get`, `newsfeed.search`,
`groups.getById`, `users.get`, `utils.resolveScreenName`. Чего не умеет:
`groups.search` (поиск сообществ) - для него нужен ключ пользователя.

Список сообществ намеренно короткий: из одиннадцати проверенных адресов годится
одно («Стрит-арт хранение»), остальное оказалось музыкальной группой, продажей
заборов, агентством маркетинга, коммерческой росписью стен и сообществами,
брошенными в 2011 и 2017 годах. Проверять кандидатов:
`py agents/vk_source.py --groups адрес1,адрес2`.

## Правила публикаций

- **«Разбор дня» не повторяется.** Событие, о котором разбор уже выходил, второй раз
  не берется никогда. Память - `data/feature_seen.json` (название, площадка, дата
  выхода). Если все события дня уже разобраны, разбор не публикуется - лучше
  пропустить день, чем повторить пост.
- **Сравнение названий - одно на весь проект**, лежит в `agents/titles.py`. Оно
  игнорирует регистр, кавычки, «е с точками» и даты, отбрасывает зачин вида
  «Выставка ...» и считает событие тем же, если короткое название входит в длинное.
  Так ловятся все три случая из жизни: «Стеклянный зверинец» и «Стеклянный
  зверинец. Спектакль в кинотеатре»; «Траектории интервалов» и «Выставка
  «Траектории интервалов»»; «Фокус: Перформанс» и «Выставка «Фокус: Перформанс» в
  MYTH». Тем же правилом публикатор склеивает дубли между своим сбором и городской
  афишей.
- Событие попадает в разобранные только после доставки в канал: сбой связи не должен
  навсегда вычеркивать событие из будущих разборов.
- Повторный прогон в тот же день ничего не публикует второй раз - утвержденный
  черновик тоже проверяется этим правилом.
- **Дайджест не повторяет событие** чаще, чем раз в 10 дней
  (`publisher.DIGEST_REPEAT_DAYS`). Дни публикаций берутся из архива
  (`data/archive/ГГГГ-ММ.jsonl`), поэтому отдельная память не нужна. Правило нужно
  потому, что афиша перестала обновляться: в августе одни и те же пять выставок
  выходили по 14 раз и занимали половину поста. Если после правила остается меньше
  трех событий, недавно показанные возвращаются, но опускаются в конец списка -
  лучше повтор, чем пустой день.
- **Подборка комиксов** (в личку, по понедельникам) помнит присланное за шесть
  недель (`data/comics_sent.json`) и передает список модели с указанием не
  повторяться. Постоянные места вроде магазинов повторяются только если они
  действительно главные.
- **Персона недели не повторяется** ближайшие полгода. Память - `data/person_seen.json`,
  срок задан в `agent4_person.COOLDOWN_WEEKS` (26 недель). Правило нужно потому, что
  выбор шел по верху недельного счетчика упоминаний, а человек из длинной выставки
  попадает туда каждую неделю: в августе один и тот же герой вышел четыре раза.
  Имена сверяются без учета порядка слов, регистра и «е с точками» - «Виталий
  Пушницкий», «Пушницкий Виталий» и «Пушницкий» это один человек, а одиночное имя
  вроде «Елена» не считается совпадением. Если все, кого упоминали за неделю, уже
  были персонами, выпуск пропускается, а владельцу уходит сообщение с причиной.
